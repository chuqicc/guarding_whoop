# 防守盯防标注协议

> **草稿 v0.1** —— 未定稿,需经校准轮修订后冻结。
> 修改记录请写在文末「版本历史」。

## 0. 这份文档怎么用

这份协议的目的只有一个:**让两个不同的人看同一段比赛,标出尽可能一致的结果。**

用法:

- **标注前通读一遍**,重点是 §4(盯防判定)。
- **标注中遇到判不了的情况**,先按 §4.4 的仲裁规则处理,然后**写进 Notes**,不要自己发明规则。
- 所有"自己发明的规则"都会变成两人之间的分歧。**宁可标错也要标得一致** —— 系统性的偏差可以在分析时校正,随机的不一致不能。

协议不是一次写成的。§10 说明怎么用软件里的对比功能找出协议的漏洞并补上。

## 1. 标注单元与基本约束

**一条标注 = 一个防守者,在一个 0.5 秒时间桶里,盯防的那一个进攻者。**

软件强制的约束,不能违反,也不必纠结:

| 约束 | 说明 |
|---|---|
| 时间精度 | **0.5 秒一格**,约 12–13 帧。换防发生在格子中间时,见 §4.5 |
| 一对一 | 一个防守者在一格里**只能指向一个**进攻者(或 GUARD_NONE) |
| 可多对一 | **多个防守者可以同时指向同一个进攻者**(包夹能表达) |
| 时钟倒数 | 格子编号从大到小,400.0 在 399.5 之前 |

**三种不同的状态,不要混淆:**

| 状态 | 含义 | 在数据里 |
|---|---|---|
| 指向某个进攻者 | 该防守者在盯这个人 | `attacker_id` = 球员号 |
| `GUARD_NONE`(∅) | **已判断**:该防守者此刻不对任何人负责 | `attacker_id` = `GUARD_NONE` |
| 留空 | **没标** | 空白 |

> ⚠️ **留空的格子会被建模流程直接丢弃**,等于白标。
> 不确定的时候要标 `GUARD_NONE` + 低置信度,**绝不能留空**。详见 §5。

---

## 2. 每节开始:先确认防守方

**这是第一件事,漏了会毁掉整节数据。**

软件默认**主队先防守**,并且**不会提示你确认**。如果这一节是主队先进攻,那么在你第一次点 ⇄ Swap teams 之前标的所有内容,攻防标签都是反的,而且没有任何警告。

**操作:**

1. 载入这一节数据后,**先播放到第一个回合**,看清楚是哪队在防守
2. 与软件右侧 Roster 面板显示的 DEF / ATT 对照
3. 不对就点 **⇄ Swap teams**
4. 之后每次攻防转换都要及时切换

**什么时候算攻防转换:**

- 投篮结束、球权确定转移之后
- 失误、抢断后球权转移之后
- 死球后重新发球,由新的进攻方发起时

> 防守方标错会导致整个回合的数据不可用(建模流程用标注反推防守方,并据此镜像球场方向)。对比两人标注时,这类分歧会被单独标为 `defense-mismatch` 并优先报出。

## 3. 排除标记:死球与出手

这三个标记**不是附注,它们决定哪些帧会进入模型**。标错等于往训练数据里掺噪声或删掉有效数据。

### 3.1 Dead(死球)—— 必标

**定义:比赛时钟停止、球不处于可争夺状态的时间段。**

| 算死球 | 不算死球 |
|---|---|
| 球出界后到重新发球 | 球在场上运行,即使没人持球 |
| 犯规哨响后到发球/罚球结束 | 抢断、争球等仍在进行的争夺 |
| 暂停 | 快攻推进过程 |
| 罚球过程 | 后场推进 |
| 节间休息 | |

**起止判据:**
- **起点** —— 哨响的那一格,或球出界的那一格
- **终点** —— 发球球员手离球的那一格(即比赛恢复的第一格)

> 死球段同时是**回合的切分点**,而回合是统计显著性检验的重采样单位。边界标得不一致会影响论文的置信区间。

### 3.2 Shot(出手)—— **必标**

**定义:投篮动作本身所占的时间段。**

- **起点** —— 投篮者开始上举出手动作的那一格
- **终点** —— 球碰篮筐那一格

出手瞬间防守关系会瞬时失真(防守者去封盖、其他人去卡位),这些帧被建模流程排除,所以**必须标准确**。

包含:跳投、上篮、扣篮、勾手、抛投。


### 3.3 Rebound(篮板)—— 可选,暂时不标

**这一项不强制。

如果标,定义为:球触框/板之后到球权重新确定之间的争抢时段。
把篮球碰到篮筐 到另外一队拿到防守篮板这一时期全部标成dead!

## 4. 盯防判定(核心)

### 4.1 总原则:判断「负责关系」,不是判断距离

问题是

> **此刻,如果这个进攻者得球得分,谁会被教练问责?**

不是"谁离得最近",也不是"谁站在篮框连线上"。**我们要提供的是几何算不出来的东西:防守意图。**

要**同时看视频和追踪动画** —— 动画告诉你位置,视频告诉你朝向、视线、身体姿态、手的动作。判断意图主要靠视频。

### 4.2 判定表(有序,首个命中即采用)

对每个防守者,按顺序问:

| # | 问题 | 命中则标 |
|---|---|---|
| 1 | 他的主要注意力是否在**持球人**身上?(贴防、封堵、干扰出手) | **持球人** |
| 2 | 他是否在**主动阻止某一个特定进攻者接球**?(手在传球路线上、身体卡在对方与球之间) | **该进攻者** |
| 3 | 他是否在**跟随某一个特定进攻者移动**,保持在其与篮框之间? | **该进攻者** |
| 4 | 他是否正在**回追、重建对某个人的防守位置**? | **该进攻者** |
| 5 | 他是否在**守区域/守篮下/对球做反应**,而不是对某个人负责? | **GUARD_NONE** |
| 6 | 他是否**尚未接管任何人**?(转换中、抢断后、发球前) | **GUARD_NONE** |

### 4.3 GUARD_NONE 的四种典型情形

`GUARD_NONE` 是本研究的重点标签,判定必须稳定。以下四类是典型的「不对任何人负责」:

**a. 协防/沉退(help / sag)**
防守者放弃自己名义上的对位,退到篮下或强侧协防位置,身体朝向球而非某个人。

**b. 区域防守(zone)**
守的是一块空间,球和人在这块空间里进出。即使某个瞬间身边站着一个进攻者,只要他的移动逻辑是"守这块地"而不是"跟这个人",就是 `GUARD_NONE`。

**c. 转换/未接管**
攻防刚转换,防守者还在回追途中,尚未确定接管对象。

**d. 完全脱离**
防守者远离所有进攻威胁(例如已经被过掉且放弃追防、或留在前场)。

> **注意区分 b 与 3**:如果他虽然守区域,但明显在**跟随某一个人移动**(人走出区域他也跟),或者眼神经常瞄向这个人,那就标那个人,不是 `GUARD_NONE`。

### 4.4 疑难仲裁

按顺序适用:

1. **夹在两个进攻者中间,都不明确** → 标**他更可能回追的那一个**(看身体朝向和重心)
2. **上一条也判不了** → 标 **`GUARD_NONE` + 置信度 1 + 写 Note**
3. **两个防守者同时盯一个人(包夹)** → **两个都标那个进攻者**。软件允许,不要为了"一人一个"硬拆
4. **名义对位 vs 实际在防** → 标**实际在防的那个人**。例如被过掉之后他去补防了另一个人,就标另一个人
5. **进攻者跑出画面/远离球** → 仍然标那个人,只要防守者还在跟

> 

### 4.5 换防、掩护、转换

**换防的时间点如何落到 0.5 秒格子上:**

换防往往发生在格子中间。规则:

> **以「新的负责关系确立」的那一格为准** —— 也就是防守者开始跟随新对象移动的第一格,而不是掩护发生的那一格。

如果一格之内同时有旧关系的尾巴和新关系的头,**看这一格里哪个关系占主导**(时间更长、更明确)。

**掩护但没换防**(挤过、绕过):对位不变,继续标原来的人,即使中间被挡住一两格。

**转换进攻**:回追途中标 `GUARD_NONE`(见 4.3c),直到明确接管某人的第一格。

## 5. 完整性

**在场的五个防守者,每一格都必须有标注。** 要么指向某人,要么 `GUARD_NONE`。

- 不确定 → `GUARD_NONE` + 置信度 1 + Note,**不要留空**
- 死球段不需要标(软件会锁住)
- 换人之后,新上场的球员从他出现的第一格开始标

**交付前自检:**

1. 用 **▬ Spells** 视图从头扫一遍,看有没有明显的空档
2. 导出 JSON 时如果报错说有标注落在没有追踪数据的格子上,按提示处理
3. 确认 **TopBar 里填了自己的名字** —— 这个名字会写进导出文件,是后续比对区分两人的唯一依据

## 6. 置信度

| 值 | 含义 | 什么时候用 |
|---|---|---|
| **3**(默认) | 确定 | 判定表第 1–4 条明确命中 |
| **2** | 比较确定 | 判断得出来,但换个人看可能有不同意见 |
| **1** | 不确定 | 用到了 §4.4 的仲裁规则 |

操作:点一个已标注的格子选中它,按 `1` / `2` / `3`。

> ⚠️ 导出时**显式的 3 和从未评分是分不出来的**。所以 3 就是默认值,只在需要降级的时候主动标 2 或 1。

## 7. Notes

**必须写 Note 的情况:**

- 用到了 §4.4 的仲裁规则(尤其是第 2 条)
- 遇到协议没覆盖的情况
- 对某段的判定自己也不服气

Note 会绑定到当前播放头所在的格子,可以选定一个防守者。

> ⚠️ 两个已知限制:Note **不能撤销**;Note **不会随导入回到会话**,导出后请自行保管 notes CSV。

## 8. Memory(carry-forward)纪律

软件默认开启 **🧠 Memory**:进入新格子时,自动把上一格的判定复制过来。这让标注快很多 —— **约 85% 的格子是自动填的**。

但它有几个危险特性:

- **没有时间上限** —— 可能从几分钟前的格子复制过来,中间跨过任意多个没标的格子
- **球权变化、换人、出手、篮板都不会中断它**,只有显式换防和死球会
- **置信度会一起复制** —— 一个"不确定"的判断会悄悄传播下去

**规则:**

> **每标完一个回合,切到 ▬ Spells 视图回看一遍该回合。**
> 检查每一段盯防的起止是否合理,有没有漏掉的换防。

原因:自动填充的格子**不是你的判断**,是软件的推测。如果两个人都不核对,那么"一致率"衡量的其实是两份自动填充算法的输出是否相同,而不是两个人的判断是否相同。

## 9. 软件已知陷阱

标注前请知悉:

| 陷阱 | 表现 | 应对 |
|---|---|---|
| 主队默认先防守 | 不提示,标反了没有警告 | §2,每节开始先确认 |
| 球场与表格对"谁在防守"判断不同 | 换防后拖回早先的格子,**球场允许你写入表格里显示为禁用的格子**,造成同一格出现两队防守者 | **换防之后回看早先片段时,用表格拖放而不是点球场** |
| 死球格子可删不可写 | 标了死球之后还能用 ✕ 清空该列 | 清空前确认 |
| 存储写满 | TopBar 出现红色 **SAVE FAILED** | 立刻导出,不要继续标 |

## 10. 校准流程

协议 v1 不可能一次写对。用软件里的 **⚖ Compare Annotators** 做反馈闭环:

```
两人各标同一节（不讨论） → 跑 Compare Annotators
                                ↓
              看四类分歧，定位协议哪一节失效
                                ↓
                  补规则 + 补实例 → 下一版
                                ↓
        直到「换防事件 F1」稳定，才开始正式标注
```

**诊断对照表:**

| 看到 | 说明 | 改协议哪一节 |
|---|---|---|
| `defense-mismatch` > 0 | 有人漏了攻防切换 | **§2,优先修**。修完其他分歧常大幅下降 |
| `coverage-mismatch` 多 | 有人留空或没标完 | §5 |
| 死球一致率低 | 对"比赛中断"理解不同 | §3.1 |
| `disagree` 集中在少数防守者 | 特定情形判定不清 | §4,补该情形的实例 |
| **换防事件 F1 低** | **核心判断不一致** | §4,这是真问题 |

**重要:**

- 建议做**两轮**校准,第二轮换一节性质不同的内容(例如转换进攻较多的)
- **校准用的节次不算进最终 reliability**,正式数字要在协议冻结后另取一节计算
- 每轮记录:协议版本、比对节次、四个指标、**改了哪一节及原因**

## 附录 A:实例库(待补)

> **这一节是协议里最重要的部分,而它只能在校准轮里长出来。**
> 判定表能让人理解规则,**实例才能让两个人标得一样。**

每条规则至少配 2 个实例,其中至少 1 个反例。格式:

```
【规则 4.2-5 → GUARD_NONE】
game_id: 00215000xx   quarter: 1   clock: 8:41.5
防守者: #23
判定: GUARD_NONE
理由: 放弃对位沉到罚球线,身体正对球,对位球员在弱侧底角无人跟随
反例对照: 同一回合 8:39.0,他开始跟随 #7 横切 → 改标 #7
```

**待补的典型情形:**

- [ ] 持球人防守(基准情形)
- [ ] 绕前切断接球
- [ ] 协防沉退 → GUARD_NONE
- [ ] 区域防守 → GUARD_NONE
- [ ] 转换未接管 → GUARD_NONE
- [ ] 包夹(两人同指一人)
- [ ] 掩护后换防(换防时点)
- [ ] 掩护但未换防
- [ ] 被过掉后补防他人
- [ ] §4.4 第 2 条仲裁(真正判不了的)
